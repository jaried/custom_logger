## 需求概述

> 作为开发者，我希望logger能够自动识别调用模块的名称，以便在子模块中直接使用主程序传入的logger，而不需要每个模块都调用get_logger。

### 澄清后的需求

| 需求项 | 说明 |
|:-------|:-----|
| 使用场景 | 子模块直接使用主程序传入的logger，无需自己调用get_logger |
| 显示模块名 | 日志中显示实际调用模块的名字（不是主程序或logger的名字） |
| 行为模式 | 动态识别 - 每次调用时获取实际调用者的模块名 |

### 验收标准

- [ ] 每次调用 logger.info() 等方法时，动态解析实际调用模块的模块名
- [ ] 日志输出中正确显示调用模块的名字（而不是主程序或logger创建时的名字）
- [ ] 复用 OPT-001 的调用栈分析函数
- [ ] 现有 get_logger(name) 方式保持兼容
- [ ] 端到端测试必须通过

---

## 选定方案

**方案1：运行时栈分析（已实施）**

使用 `traceback.extract_stack()` 和 `inspect.stack()` 获取完整调用栈，从栈帧中提取实际调用者的模块名，在日志格式化时使用动态解析的模块名。

**核心思路**：
1. 复用现有的 `get_caller_info()` 函数（已实现调用栈分析）
2. 修改 `create_log_line()` 函数第241行
3. 使用动态获取的 `caller_module` 替代传入的固定 `module_name`

**理由**：
- 行为统一，用户不需要关心 logger 的创建方式
- 复用现有函数，代码改动最小
- 性能开销可接受（与 OPT-001 一致，~50µs/次）

## 集成设计

### 集成点

| 链路位置 | 上游环节 | 下游环节 | 接口类型 | 涉及文件 |
|:---------|:---------|:---------|:---------|:---------|
| 1→2 | 用户调用 | 获取调用栈 | 函数调用 `_log()` | logger.py:297 |
| 2→3 | 获取调用栈 | 提取模块名 | 函数调用 `get_caller_info()` | formatter.py:28 |
| 3→4 | 提取模块名 | 创建日志行 | 内部数据传递 | formatter.py:241 |
| 4→5 | 创建日志行 | 输出日志 | 函数调用 `write_log_async()` | writer.py |

### 接口契约

#### 集成点 2→3：get_caller_info()

```python
def get_caller_info() -> Tuple[str, int]:
    """获取调用者信息（文件名和行号）

    Returns:
        Tuple[str, int]: (模块名, 行号)
            - 模块名来自文件basename，截断到16字符
            - 异常时返回 ("error", 0)
    """
```

#### 修改点：create_log_line()

```python
# 原代码（第241行）：
log_line = f"[{pid_str:>6} | {module_name:^16} : {line_number:>4}] ..."

# 修改后：
log_line = f"[{pid_str:>6} | {caller_module:^16} : {line_number:>4}] ..."
```
