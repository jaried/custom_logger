## 1. 需求背景

> 作为开发者，我希望日志过期清理结果能按合适的空间单位显示，以便更直观地查看实际释放空间。

**验收标准**：
- [ ] 释放空间小于 1 MB 时按 KB 显示
- [ ] 释放空间大于等于 1 MB 时按 MB 显示
- [ ] 数值保留两位小数
- [ ] 清理日志仍包含删除目录数量
- [ ] 端到端测试必须通过（禁止跳过端到端测试）

**关联背景**：
- `US-001` 已建立日志过期清理能力，并要求输出删除目录数量与释放空间摘要
- `US-003` 已建立初始化成功日志输出能力，但该信息与本次空间单位展示无直接改动关系

### 2.2 当前实现现状

当前 `cleanup_expired_logs()` 的摘要日志流程为：
1. 删除过期目录后得到 `deleted_count` 与 `freed_bytes`
2. 将 `freed_bytes` 固定换算为 `freed_kb`
3. 通过 `logger_instance.info()` 输出 `"释放 {freed_kb:.2f} KB 空间"`

**现状证据**：
- `src/custom_logger/log_cleaner.py:246`：清理函数拿到 `deleted_count, freed_bytes`
- `src/custom_logger/log_cleaner.py:255`：当前固定计算 `freed_kb`
- `src/custom_logger/log_cleaner.py:257`：当前固定输出 `KB`
- `src/custom_logger/manager.py:117`：初始化成功日志在 `manager` 中单独输出，和本次空间单位展示无耦合

### 2.4 第一性原理分析

**issue描述**：日志过期清理完成时，如果释放空间已经达到 MB 级别，继续显示大数字 `KB` 不够直观。

**根本问题**：当前摘要日志的**可读性不足**，而不是清理逻辑、目录删除逻辑或空间统计逻辑错误。

**基本要素**：
- 日志展示的唯一真源是 `freed_bytes`
- 用户关注的是“释放了多少空间”，不是内部使用何种计量单位
- 该需求是展示层优化，不应扩大为清理逻辑重构

**设计方向**：基于根本问题，设计应聚焦于**在日志摘要拼装阶段进行单位切换**，并保持清理链路与初始化链路不变。

## 6. 方案选择

### 备选技术方案

| 方案 | 核心思路 | 优点 | 缺点 | 推荐 |
|:-----|:---------|:-----|:-----|:-----|
| 方案1 | 在 `cleanup_expired_logs()` 中直接内联 `if/else` 判断 `KB/MB` | 改动行数最少 | 逻辑分散，不利于单元测试和后续复用 | ⭐⭐ |
| 方案2 | 在 `log_cleaner.py` 中新增模块内辅助函数 `_format_released_space(freed_bytes)`，日志拼装前统一调用 | 职责清晰、便于单元测试、避免 magic number 分散 | 比纯内联多一个辅助函数 | ⭐⭐⭐ |

**选定方案**：方案2 - 模块内空间单位格式化辅助函数

**核心思路**：
- 在 `src/custom_logger/log_cleaner.py` 内新增 `_format_released_space(freed_bytes: int) -> str`
- 由该函数统一负责阈值判断、单位切换和两位小数格式化
- `cleanup_expired_logs()` 只负责拿到 `deleted_count` / `freed_bytes` 后调用该函数，保持主流程职责单一

**选择理由**：
- 直接命中“日志可读性不足”的根本问题
- 不引入配置项，不改变已有清理逻辑
- 方便后续通过单元测试覆盖阈值、边界值和非法值

**建议实现草图**：

```python
ONE_KB = 1024
ONE_MB = 1024 * 1024


def _format_released_space(freed_bytes: int) -> str:
    if freed_bytes < 0:
        raise ValueError("freed_bytes 不能为负数")
    if freed_bytes >= ONE_MB:
        return f"{freed_bytes / ONE_MB:.2f} MB"
    return f"{freed_bytes / ONE_KB:.2f} KB"
```

**实施注意点**：
- 阈值判断应在 `bytes` 层完成，避免二次换算引入歧义
- 摘要日志只替换单位字符串，不改变 `deleted_count` 与调用位置
- 继续保持 INFO 级别，不新增额外日志
