## 需求概述

> 作为开发者，我希望warning级别的日志能记录调用栈，以便更好地追踪问题来源。

### 验收标准

- [ ] warning级别记录调用栈（使用 `traceback.extract_stack()`）
- [ ] error及以上级别保持原有错误栈行为（使用 `sys.exc_info()`）
- [ ] exception级别保持原有行为
- [ ] 调用栈格式完整（文件名:行号 函数名）
- [ ] 端到端测试必须通过

### 设计变更说明

**2026-02-02 更新**：
- 复用 `_get_call_stack_info()` 的实现方式（`traceback.extract_stack()`）
- 只针对 WARNING 级别添加调用栈
- ERROR及以上级别保持94a8a38提交的错误栈实现不变

## 选定方案

**方案：WARNING级别使用调用栈，ERROR+保持错误栈不变**

**核心思路**：
1. 新增 `formatter.get_call_stack()` 函数（复用 `_get_call_stack_info()` 的实现方式）
2. 修改 `logger._log()` 方法：
   - `level_value == WARNING`：调用 `get_call_stack()`
   - `level_value >= ERROR`：调用 `get_exception_info()`（保持原有实现）

**理由**：
- 复用已验证的 `_get_call_stack_info()` 实现方式
- WARNING级别获取调用栈，便于追踪警告来源
- ERROR及以上保持原有错误栈行为，不破坏已有功能

## 集成设计

### 接口契约

#### 新增接口：formatter.get_call_stack()
```python
def get_call_stack() -> str:
    """获取当前调用栈信息（用于WARNING级别）

    复用 _get_call_stack_info() 的实现方式，使用 traceback.extract_stack()
    获取完整调用栈，过滤掉logger内部调用，只保留用户代码。

    Returns:
        str: 格式化的调用栈，或空字符串（获取失败时）
    """
```

#### 修改接口：logger._log()
```python
# 新逻辑（需要实现）
exception_info = None
if level_value == WARNING:
    # WARNING级别：使用调用栈
    call_stack = get_call_stack()
    if call_stack:
        exception_info = call_stack
elif level_value >= ERROR:
    # ERROR及以上：使用错误栈（原有实现）
    exception_info = get_exception_info()
```
