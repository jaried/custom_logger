## 需求概述

> 作为开发者，我希望warning及以上级别的日志都能记录调用栈，以便更好地追踪问题来源。

### 验收标准

- [ ] warning级别记录调用栈
- [ ] error级别记录调用栈
- [ ] critical级别记录调用栈
- [ ] exception级别保持原有行为
- [ ] 调用栈格式完整（文件名:行号 函数名）
- [ ] 端到端测试必须通过

---

## 现状分析

**现有实现**（`logger.py:331-334`）：
```python
# 获取异常信息（WARNING级别及以上）
exception_info = None
if level_value >= WARNING:
    exception_info = get_exception_info()
```

**问题分析**：
- `get_exception_info()` 使用 `sys.exc_info()`，只在异常上下文中有效
- 普通warning/error调用（非异常上下文）无法获取调用栈

**技术验证**：
- ✅ `traceback.extract_stack()` 可以获取完整调用栈
- ✅ 性能可接受（平均52µs）
- ✅ 格式化输出符合要求

---

## 选定方案

**方案1：始终获取完整调用栈**

使用 `traceback.extract_stack()` 获取完整调用栈，无论是否在异常上下文中，warning及以上级别都记录完整调用信息。

**核心思路**：
1. 新增 `formatter.get_call_stack()` 函数
2. 修改 `logger._log()` 方法，WARNING级别及以上调用 `get_call_stack()`
3. exception级别保持使用 `sys.exc_info()`（原有行为）

**理由**：
- 行为统一，便于追踪问题来源
- 性能开销可接受（~50µs/次）
- 满足验收标准

## 集成设计

### 接口契约

#### 新增接口：formatter.get_call_stack()
```python
def get_call_stack() -> str:
    """获取当前调用栈信息

    Returns:
        str: 格式化的调用栈，或空字符串（获取失败时）
    """
```

#### 修改接口：logger._log()
- 在 `level_value >= WARNING` 时调用 `get_call_stack()`
- exception级别保持使用 `sys.exc_info()`

### 集成顺序

1. 第一批：formatter.py 新增 `get_call_stack()` 函数
2. 第二批：logger.py 修改 `_log()` 方法调用 `get_call_stack()`
3. 第三批：logger.py 修改 warning/error/critical 方法（无需修改，自动生效）
