# OPT-001 测试设计

**关联issue**：OPT-001
**设计日期**：2026-02-02
**测试策略**：分层测试（单元→集成→E2E）

---

## 1. 单元测试设计

### 测试目标
验证 `get_call_stack()` 函数能正确获取和格式化调用栈信息。

### 测试用例

| 测试用例ID | 场景类型 | 测试场景 | 输入 | 预期输出 |
|:-----------|:---------|:---------|:-----|:---------|
| UT-001 | 正常 | 典型warning调用 | logger.warning("test") | 返回格式化调用栈字符串 |
| UT-002 | 正常 | 深层嵌套调用 | 5层嵌套调用 | 包含完整调用链 |
| UT-003 | 边界 | 单层调用 | 直接调用 | 最小调用栈 |
| UT-004 | 边界 | 深度嵌套 | 20层嵌套 | 完整调用栈不截断 |
| UT-005 | 异常 | 空调用栈 | 无法获取栈 | 返回空字符串 |
| UT-006 | 异常 | 权限错误 | 无权限访问栈 | 返回错误提示 |

## 2. 集成测试设计

### 测试目标
验证warning及以上级别与_log方法的集成，调用栈正确附加到日志。

### 测试用例

| 测试用例ID | 场景类型 | 测试场景 | 预期结果 |
|:-----------|:---------|:---------|:---------|
| IT-001 | 正常 | warning级别记录调用栈 | 日志包含调用栈 |
| IT-002 | 正常 | error级别记录调用栈 | 日志包含调用栈 |
| IT-003 | 正常 | critical级别记录调用栈 | 日志包含调用栈 |
| IT-004 | 正常 | exception保持原有行为 | 日志包含异常信息 |
| IT-005 | 边界 | 无异常上下文warning | 使用extract_stack() |
| IT-006 | 边界 | 有异常上下文error | 使用sys.exc_info() |

## 3. 端到端测试设计

### 测试目标
验证完整日志系统从调用到文件输出的全流程。

### 测试用例

#### E2E-001: warning级别记录调用栈
- **场景类型**：正常
- **前置条件**：logger系统已初始化
- **测试步骤**：
  1. 创建logger实例
  2. 调用logger.warning("测试警告")
  3. 读取日志文件
- **通过标准**：日志包含warning消息和完整调用栈（文件:行号 函数名）

#### E2E-002: error级别记录调用栈
- **场景类型**：正常
- **前置条件**：logger系统已初始化
- **测试步骤**：
  1. 创建logger实例
  2. 调用logger.error("测试错误")
  3. 读取日志文件
- **通过标准**：日志包含error消息和完整调用栈

#### E2E-003: exception级别保持原有行为
- **场景类型**：正常
- **前置条件**：logger系统已初始化
- **测试步骤**：
  1. 创建logger实例
  2. 在try-except中调用logger.exception("测试异常")
  3. 读取日志文件
- **通过标准**：日志包含异常信息和异常堆栈（使用sys.exc_info()）

#### E2E-004: 深层嵌套调用栈完整性
- **场景类型**：边界
- **前置条件**：logger系统已初始化
- **测试步骤**：
  1. 创建多层嵌套函数（5层以上）
  2. 在最内层调用logger.warning
  3. 读取日志文件
- **通过标准**：调用栈包含完整的调用链

#### E2E-005: 性能验证
- **场景类型**：边界
- **前置条件**：logger系统已初始化
- **测试步骤**：
  1. 连续调用100次logger.warning
  2. 测量总耗时
- **通过标准**：平均每次调用耗时 < 100µs
