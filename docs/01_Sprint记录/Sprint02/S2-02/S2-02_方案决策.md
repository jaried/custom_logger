## 2. 原始需求与最终结果

原始需求要求降低普通日志获取调用者文件名和行号的同步开销，同时保持调用位置和可选完整调用链语义。消费项目的 py-spy 证据指出当前 `get_caller_info()` 的 `inspect.stack()` → `inspect.getframeinfo()` → `linecache.checkcache()` 链路存在可观测同步开销；该采样权重不是端到端等待时间，不能直接折算成收益百分比。

本 Issue 只交付一个结果：**普通日志不再为调用者定位构造完整 `inspect.stack()`，同时保持受支持的真实日志调用点、完整调用链和既有日志 Interface 不变，并用固定无 I/O 场景证明候选定位 Implementation 的耗时低于基线。**

### 2.1 稳定术语

- **Module**：本 Issue 的目标 Module 是 `src/custom_logger/formatter.py::get_caller_info()`；函数本身是 Module。
- **Interface**：无参数调用，返回 `(模块名, 行号)`；Interface 还包含过滤规则、失败返回、调用链诊断开关影响及普通路径性能特征。
- **Seam**：`create_log_line()` 调用 `get_caller_info()` 的位置。该 Seam 不移动。
- **Implementation**：`get_caller_info()` 内部如何获取和扫描 Python frame；本 Issue 只替换这一部分。
- **真实日志调用点**：业务 Module 在事件发生处直接调用 `logger.<level>()` 的源码行。
- **完整调用链**：`show_call_chain` 或 `show_debug_call_stack` 触发时，由现有诊断路径生成的链路文本。

### 2.2 受支持的 logger 使用方式

以 `py-config-logger` 为权威使用契约：

1. 每个使用日志的业务 Module 在 logger 系统初始化完成后导入，文件头只获取一次 `logger = get_logger("name")`。
2. 事件发生处直接调用同一个 `logger.<level>()`。
3. 禁止 facade、adapter、helper、回调或延迟 getter 代调 logger，也禁止显式把 logger 传入其他 Module 作为日志回调。
4. 因此 S2-02 **不承诺识别或跳过用户自建 logger wrapper**，也不新增 `stacklevel`、wrapper 注册表或用户帧跳过配置。若用户违反该使用契约，位置自然落在实际执行 `logger.<level>()` 的 wrapper 行；该行为不是本 Issue 的兼容目标。

## 3. 权威栈契约与现状偏差

### 3.1 `py-config-logger` 权威栈契约

- DETAIL / DEBUG / INFO：不附加异常栈或调用栈。
- WARNING：仅当 `cfg.logger.show_warning_stack=true` 时附加当前调用栈，默认 `false`。
- ERROR / CRITICAL / EXCEPTION：始终自动附栈；存在活动异常时优先输出异常 traceback，否则输出当前调用栈。
- `show_call_chain` 与 `show_debug_call_stack` 只用于 logger 自身的调用者识别诊断，不能替代 `show_warning_stack`。

### 3.2 当前 `sprint02` 代码的既有偏差

本次评审确认当前基线存在与上述契约不一致的历史实现：

- `logger.py::_log()` 当前对 WARNING 无条件调用 `get_call_stack()`，没有按 `show_warning_stack` 控制。
- `logger.py::_log()` 当前 ERROR / CRITICAL / EXCEPTION 在没有活动异常时只得到 `None`，没有补当前调用栈。
- 当前 `config.py::DEFAULT_CONFIG['logger']` 未包含 `show_warning_stack`。
- `tests/test_custom_logger/test_tc0021_error_stack_trace.py` 中部分断言固化了上述旧行为。

这些偏差在 S2-02 登记前已存在，且与“降低调用者定位同步开销”不是同一业务结果。为保持 Issue 原子性，**S2-02 不修改 `logger.py`、`config.py` 或 WARNING/ERROR 栈契约测试，不把旧实现重新定义为正确契约，也不宣称本 Issue 修复这些偏差。** 当前 Issue 内登记为遗留问题 `LEGACY-S2-02-01`，供后续显式处理；不在本次自动新增 Issue。

S2-02 的 Implementation 只能保证：caller 定位改造不得触碰或进一步改变这些栈路径。

## 4. 已验证代码事实

1. `get_caller_info()` 当前每条实际日志都会调用 `inspect.stack()`，读取 `FrameInfo.filename`、`lineno` 并执行过滤。
2. `create_log_line()` 每次生成日志行时调用 `get_caller_info()`；`CustomLogger._log()`、队列 writer 和普通 writer 均不拥有 caller 识别规则。
3. 当前 caller 规则依次包含：测试文件特殊处理、custom_logger 内部帧识别、框架帧过滤、mock 帧过滤、模块名最多 16 字符、内部帧回退、`unknown`/`error` 默认返回。
4. `_get_call_stack_info()`、`get_call_stack()`、`get_exception_info()` 是与普通 caller 定位不同的 Implementation 路径；显式开启诊断或相应日志级别时才需要完整栈。
5. `tests/01_unit_tests/test_tc0019_call_chain.py` 的异常用例当前 patch `inspect.stack`，改造后该注入点必须机械改为 `inspect.currentframe`。
6. `tests/test_custom_logger/test_tc0022_dynamic_module_name.py` 包含“函数内 get_logger / 显式传 logger”历史用法，不符合当前 `py-config-logger` 使用契约；它可以作为历史回归输入运行，但不得作为 S2-02 新 Interface 的规范来源。

## 5. `codebase-design` 结构决策

### 5.1 Module / Interface / Seam

S2-02 保持现有结构，不新增外部结构：

- Module：`get_caller_info()`。
- Interface：`get_caller_info() -> Tuple[str, int]` 及其既有行为契约。
- Seam：`create_log_line()` → `get_caller_info()`。
- Implementation：从 `inspect.stack()` 替换为 raw frame 遍历。
- Adapter：不新增。当前不存在第二种可替换 Implementation，不建立假想 Seam。

### 5.2 Depth / Leverage / Locality

- **Depth**：caller 过滤、内部帧识别、失败回退、诊断开关等复杂性继续隐藏在单一 `get_caller_info()` Interface 后面。
- **Leverage**：所有日志级别通过同一日志行生成路径复用该 Interface；调用者无需学习 frame 细节。
- **Locality**：生产差量只落在 `formatter.py::get_caller_info()`，不把 caller 识别逻辑散到 `logger.py`、writer、queue 或业务调用方。
- **Deletion test**：若删除该 Module，caller 识别与过滤规则必须重新散落到日志行生成或各日志级别调用路径，因此该 Module 有实际价值，不是 pass-through。
- **Interface is the test surface**：新增测试只跨 `get_caller_info()` / `create_log_line()` 已有 Interface 验证；不为测试暴露 private frame scanner，不新增测试专用生产入口。

### 5.3 明确拒绝的结构方向

- 不新增 caller-location class、策略对象、Adapter、缓存 Module 或第二个公共 Interface。
- 不在 `CustomLogger` 增加 `stacklevel` 或 caller 参数。
- 不把 frame 传给 writer/queue，也不把 caller 定位延后到异步线程或子进程。
- 不缓存“模块名 + 行号”：行号是调用点状态，缓存会引入失效规则和错误位置风险。
- 不使用用户 wrapper 白名单/黑名单扩展 Interface。

## 6. 选定方案 v2

### 6.1 方案 A：在原 Interface 内以 raw frame 单次扫描替换 `inspect.stack()`

`get_caller_info()` 使用 `inspect.currentframe()` 取得当前 frame，并从 `f_back` 开始沿 raw frame 链扫描。设计和实施必须机械遵守以下规则：

1. **Interface 不变**：函数名、参数、返回类型、`create_log_line()` 调用方式均不变。
2. **只扫描 raw frame**：普通路径不得调用 `inspect.stack()`、`inspect.getframeinfo()` 或主动读取源码上下文；每个 frame 只读取 `f_code.co_filename`、`f_lineno`，必要时读取 `f_code.co_name`。
3. **扫描完整链一次**：从 `currentframe().f_back` 直到 `None` 做一次线性扫描。即使已经找到第一个 caller 候选，也继续扫描剩余 frame 以保持当前“调用链中任意文件名包含 `test_tc` 即视为测试环境”的诊断语义；但不得再次扫描第二遍。
4. **caller 选择不被后续 frame 覆盖**：第一个按现有顺序满足条件的候选被记录后保持不变；继续扫描只用于测试环境标记，不改变 caller 选择。
5. **测试环境标记**：对扫描到的每个上游 frame，在其他过滤前检查 filename 是否包含 `test_tc`；任一命中则 `in_test=True`。
6. **行号规则**：`f_lineno <= 0` 或 `f_lineno > 10_000` 的 frame 不参与 caller 选择，与当前行为一致。
7. **测试文件特殊规则**：若 caller 选择尚未完成，且 `os.path.splitext(os.path.basename(filename))[0].startswith("test_tc")`，记录 `("test_tc0", line_number)` 作为 caller；后续 frame 不覆盖。
8. **custom_logger 内部规则**：保持现有判定表达式和文件集合不变：规范化路径含 `custom_logger`，且 basename 属于 `logger.py`、`formatter.py`、`writer.py`、`config.py`、`manager.py`，或 basename 以 `module` / `internal` 开头。内部 frame 只保存 `(name_without_ext, line_number)` 原始值，不保存 frame 对象；如最终没有外部 caller，使用扫描过程中最后一个内部 frame，并将模块名截断到 16 字符。
9. **框架规则**：保持现有 `framework_files` 集合和 `<string>` 判断不变；本 Issue 不增删框架名称。
10. **mock 规则**：`name_without_ext.lower()` 包含 `mock` 时继续跳过，保持现状。
11. **普通 caller**：第一个非内部、非框架、非 mock 的 frame 成为 caller；模块名仍最多 16 字符。
12. **空 frame**：`inspect.currentframe()` 返回 `None` 时直接返回 `("main", 0)`，不进入诊断配置读取，与当前空栈语义一致。
13. **无 caller**：没有外部 caller 且没有内部 fallback 时返回 `("unknown", 0)`。
14. **异常**：frame 获取、访问或扫描抛出异常时返回 `("error", 0)`；若 `show_call_chain=true`，继续输出既有 `[调用链异常] ...` 标记。
15. **诊断输出顺序**：扫描结束后仍按当前顺序先处理 `show_call_chain` 的 `[调用链]`，再在 `in_test` 且 `show_debug_call_stack=true` 时处理 `DEBUG: get_caller_info调用链:`；两者继续调用既有 `_get_call_stack_info()`，S2-02 不改变其文本格式。
16. **raw frame 生命周期**：Implementation 不允许把 frame 对象放入 list、tuple、闭包、全局状态或返回值；只保存字符串、整数和布尔值。持有的起始 frame / 当前 frame 引用必须在 `finally` 中显式删除，确保 caller 定位不会因局部 frame 引用延长引用环生命周期。
17. **不新增生产 helper**：本 Issue 不增加新的生产 Module / Interface / Seam；扫描和选择仍属于 `get_caller_info()` 的内部 Implementation。设计阶段不得再选择“是否抽 helper”。
18. **栈契约不在此处重写**：`get_call_stack()`、`get_exception_info()`、`logger.py::_log()` 和配置字段不改；`LEGACY-S2-02-01` 保持显式未解决。

## 8. 测试决定

### 8.1 新聚焦测试：`test_s2_02_caller_info.py`

文件名明确**不以 `test_tc` 开头**，避免命中生产代码现有测试特判。测试必须通过公开/既有 Interface 完成，不测试 private Implementation。

固定覆盖：

1. `get_caller_info()` 在该测试文件直接调用时返回模块名 `test_s2_02_call...` 的 16 字符截断值和实际调用行号。
2. 通过普通 Python 函数增加一层调用深度后，返回实际执行 `get_caller_info()` 的函数所在文件与调用行；该函数仅用于测试 Module Interface，不包装 `logger.<level>()`，不构成受支持业务 logger wrapper。

4. patch `custom_logger.formatter.inspect.stack` 和 `inspect.getframeinfo` 为抛异常时，普通定位仍成功，证明普通路径不依赖两者。

6. patch `inspect.currentframe` 抛异常时得到 `("error", 0)`；开启 `show_call_chain` 时保留 `[调用链异常]`。
7. 构造超过 16 字符的模块名场景，截断语义不变。
8. 普通配置关闭 `show_call_chain` / `show_debug_call_stack` 时，不输出完整诊断调用链。

### 9.1 基线与候选

### 9.2 timed scope

只计时 `get_caller_info()` Interface 调用本身；以下全部放在计时区间外：logger 系统初始化/销毁、配置构造、import、文件/控制台 I/O、JSON 写入和结果断言。

- `show_debug_call_stack=false`

### 9.3 固定输入

benchmark 只测 caller-location Module，不包装 logger：

- Case A：benchmark 函数直接调用 `get_caller_info()`。
- Case B：`outer_probe()` 调用 `inner_probe()`，由 `inner_probe()` 调用 `get_caller_info()`；用于验证 frame 深度变化下的扫描成本，不代表业务允许 wrapper logger。

### 9.4 固定次数与统计

每个 Git ref、每个 Case：

1. 预热 `10_000` 次，不计时。
2. 运行 `7` 个独立 round。
3. 每个 round 调用 `100_000` 次。
4. 每个 round 使用 `time.perf_counter_ns()` 记录总纳秒，并换算 `ns/call`。
5. 使用标准库 `statistics.median` 计算 7 个 round 的 median，同时记录 min、max 和各 round 原始值。

### 9.5 性能通过条件

先通过所有正确性断言，再判断性能。**Case A 与 Case B 的 candidate median `ns/call` 都必须严格低于对应 baseline median**；不设置未经测量的百分比目标。任一 Case 未降低即 AC-S2-02-03 不通过，不得以消费项目 py-spy 的 0.92 样本秒替代本地对照结果。

原始 JSON 至少包含：Git ref、`sys.version`、`platform.platform()`、配置开关、warmup、rounds、iterations、每 round `ns/call`、median/min/max、caller 结果和断言状态。

## 10. 最终验收标准

- **AC-S2-02-01 — Interface 与调用位置**：`get_caller_info() -> Tuple[str, int]`、`create_log_line()` 和 `CustomLogger` 对调用方的 Interface 不变；受支持的“业务 Module 文件头获取一次 logger、事件点直接调用”路径继续显示实际日志调用文件和行号。
- **AC-S2-02-02 — 普通路径去除完整栈构造**：普通 caller 定位不调用 `inspect.stack()`、`inspect.getframeinfo()` 或源码上下文读取；聚焦测试通过，显式诊断调用链仍可按原开关走既有 `_get_call_stack_info()`。
- **AC-S2-02-03 — 性能**：严格按 `#9` 协议，Case A 与 Case B 的 candidate median 均低于 baseline，且 correctness 先通过。
- **AC-S2-02-04 — frame 生命周期**：生产 Implementation 不保存 frame 对象，只保存 primitive 结果；所有 raw frame 局部引用在 `finally` 显式删除，无新增全局/缓存 frame 状态。
- **AC-S2-02-05 — Codebase Design**：Module、Interface、Seam 保持 `#5` 决策；不新增 Adapter、公共 caller Interface、缓存 Module、writer/queue caller 逻辑或测试专用生产 Seam；测试跨既有 Interface。
- **AC-S2-02-06 — 栈契约不被篡改**：S2-02 文档以 `py-config-logger` 为权威明确 WARNING 可选、ERROR 及以上自动附栈；生产差量不修改 `logger.py` / `config.py`，`LEGACY-S2-02-01` 仍明确未解决，不把历史错误行为写成新规范。
- **AC-S2-02-07 — 回归**：`test_s2_02_caller_info.py`、更新后的 `test_tc0019_call_chain.py` 通过，并完成全量项目测试；不存在由 S2-02 差量新增的测试失败。
