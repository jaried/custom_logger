# S2-01 设计：初始化日志目录输出追加目录分隔符

## 1. 需求背景

## 2. 现状分析

当前 `init_custom_logger_system` 从 `config_object.paths.log_dir` 读取目录值（`src/custom_logger/manager.py:35-47`），普通模式调用 `init_writer()`（`103-108`），队列模式调用 `init_queue_receiver(log_queue, log_dir)`（`77-100`），随后注册退出清理并设置 `_initialized = True`（`110-113`）。统一成功提示在 `manager.py:115-119` 通过 `get_logger("manager").info(...)` 输出，当前直接插入原始 `log_dir`。

该收敛点已经处于普通/队列初始化分支之后，因此只改变提示构造即可满足显示边界，而不会把带分隔符的值传给 writer 或 queue receiver。当前回归测试位于 `tests/01_unit_tests/test_tc0030_init_log_path.py:15-240`；队列与普通模式时序回归位于 `tests/01_unit_tests/test_tc0018_enable_queue_mode_config.py`。

设计阶段证据：

- S2-01 目录显示与真实 E2E：`9 passed`。
- 队列/普通/worker/异常配置回归：`10 passed`。
- 规范化独立验证：无尾、`/` 尾、`\\` 尾和混合尾输入均输出一个 Windows `os.sep`，原始样例保持不变。
- 具体命令与原始结果见 `技术验证/验证记录.md`。

## 3. 约束集

约束全部承接方案决策 `S2-01_方案决策.md#6`：

- 成功提示继续使用现有 `logger.info`，文件名文本仍为 `full.log`、`warning.log`。
- 目录显示值恰好保留一个结尾目录分隔符；优先使用运行平台原生 `os.sep`。
- 规范化只作用于显示值，不写回 `config_object.paths.log_dir`。
- 普通模式、队列模式的初始化时序、writer/receiver 参数和错误处理保持不变。
- 只维护一处显示格式化逻辑；不新增类、公共 API、配置迁移、ADR 或前端原型。
- 只修改方案决策 `#10` 指定的生产文件和测试文件。

## 6. 详细设计

### 6.1 选定方案

在 `src/custom_logger/manager.py` 增加标准库 `os` 导入，并在 `manager.py:115` 附近、现有 `logger.info` 调用前计算：

```python
display_log_dir = str(log_dir).rstrip("/\\") + os.sep
```

提示字符串只引用 `display_log_dir`：

```python
f"日志系统初始化成功，日志目录: {display_log_dir}, 文件: full.log, warning.log"
```

实现边界：

1. `str()` 支持现有字符串以及可转为字符串的路径对象。
2. `rstrip("/\\")` 仅清理显示值末尾已有的两种允许分隔符，避免双分隔符。
3. `os.sep` 提供平台原生显示分隔符；用户验收按 `\\` 或 `/` 允许集合判断。
4. 不重新赋值 `log_dir`，不修改 `config_object.paths.log_dir`。
5. 不移动 `_initialized`、退出清理、普通/队列分支或异常处理。

### 7.2 集成设计

本 issue 无跨服务或外部 API 集成，集成边界是 manager 内部的“原始路径消费”和“显示路径输出”两种不同契约：

| 集成点 | 上游契约 | 下游契约 | 保持不变项 |
|:---|:---|:---|:---|
| D1→D2 | `log_dir` 为配置原始值 | writer/receiver 继续接收原始值 | 文件落盘路径、队列参数 |
| D2→D3 | 初始化成功后注册清理并设状态 | 成功提示只在状态收敛后执行 | 时序、失败传播 |
| D3→D4 | 原始值只读 | 生成局部 `display_log_dir` | 配置对象值 |
| D4→D5 | 一个规范化显示值 | `logger.info` 输出固定提示 | logger 名称、级别、文件名文本 |

集成顺序按 D1→D2→D3→D4→D5；D4 是唯一新增逻辑，失败时不引入新异常分支。初始化错误仍由现有外层 `try/except` 捕获并重新抛出。
