# OPT-001 统一warning及以上级别记录调用栈 - 设计方案

## 需求概述

> 作为开发者，我希望warning及以上级别的日志都能记录调用栈，以便更好地追踪问题来源。

## 现状分析

### 当前实现

文件：`src/custom_logger/logger.py:331-334`

```python
# 获取异常信息（ERROR级别及以上）
exception_info = None
if level_value >= ERROR:  # ERROR=40
    exception_info = get_exception_info()
```

### 日志级别定义

| 级别 | 数值 | 当前是否记录调用栈 |
|:-----|:-----|:-------------------|
| WARNING | 30 | ❌ 否 |
| ERROR | 40 | ✅ 是 |
| CRITICAL | 50 | ✅ 是 |
| EXCEPTION | 60 | ✅ 是 |

## 设计方案

### 修改内容

将判断条件从 `ERROR(40)` 改为 `WARNING(30)`：

```python
# 修改前
if level_value >= ERROR:

# 修改后
if level_value >= WARNING:
```

### 修改位置

- 文件：`src/custom_logger/logger.py`
- 行号：332

### 影响范围

| 级别 | 修改后是否记录调用栈 |
|:-----|:---------------------|
| WARNING | ✅ 是（新增） |
| ERROR | ✅ 是（不变） |
| CRITICAL | ✅ 是（不变） |
| EXCEPTION | ✅ 是（不变） |

## 测试策略

### 单元测试

1. 验证 warning 级别调用 `get_exception_info()`
2. 验证 error/critical/exception 行为不变

### 端到端测试

1. 调用 `logger.warning()` 验证输出包含调用栈
2. 调用 `logger.error()` 验证输出包含调用栈（回归）

## 风险评估

- **风险等级**：低
- **原因**：仅扩展功能，不改变现有行为
